# teach-by-analogy

一个给 AI 编程助手 / Agent 用的 **skill**：当学生被复杂公式、拗口名词或抽象机制卡住时，用生活化类比把人讲懂，而不是把答案丢过来。

适用于 DeepSeek Harness（DSH）、Claude Code 等支持 `SKILL.md` 约定的 agent 运行时。

---

## 它解决什么问题

大部分 AI 讲题有三个毛病：

1. **用更难的词解释难词**——「自注意力就像 attention mechanism」，零信息。
2. **气场类比**——「神经网络像大脑」「量子纠缠像心灵感应」，只共享形容词，推不出任何结论。
3. **默认你懂名词**——「因为它是凸的，所以有全局最优」，而「凸」你没懂，还以为是自己的问题。

这个 skill 把「打个比方」从随口一说，变成一条可检查的工序。

## 核心设计

### 五条铁律

| # | 规则 | 一句话 |
|---|---|---|
| 1 | 先例子，后概念 | 先用生活场景演一遍，再搬到你要学的东西上 |
| 2 | 比方必须是同一个骨架 | 不是「听起来像」，是「关系结构一样」 |
| 3 | 宁可没有比方，也不要坏比方 | 漂亮但错的比方，纠正成本远高于「暂时不懂」 |
| 4 | 比方只用来解释，不用来证明 | 「在比方里成立」不是有效推理 |
| 5 | 不默认学生懂名词 | 没解释过的名词，不能拿来解释新名词 |

### 输出前的四道门

每个比方发出去之前先过一遍，静默自检：

- **① 角色数一致**：比方的角色能否与目标角色一一对上？
- **② 作用方向一致**：是否需要「反过来看」才讲得通？（需要 = 立刻换，反向映射几乎必然教错）
- **③ 可推演**：能用这个比方推出一条**新**结论并回到原概念验证吗？
- **④ 失效同址**：比方在哪里开始不成立？那里是否正好对应概念的边界？

通过线：**①②③ 必须全过，④ 至少要说清。**

再加一条**删除测试**：把比方整段删掉，学生的理解会不会变差？不变就是装饰，删掉。

### 映射表

禁止形容词（像、类似、差不多），必须写关系（都是按比例分配 / 都是一次加总 / 都先归一化再合并）：

| 生活场景 | 对应物 | 为什么对得上 | 能推出的结论 | 开始不像的地方 |
|---|---|---|---|---|

### 名词拆解

学生不懂某句话时，不解释整句，而是**把名词挖成槽**再逐个钉义：

```
原句：__①__ 在 __②__ 的条件下，通过 __③__ 得到 __④__
```

每个槽给五行：哪类东西 / 在这句里什么角色 / 回答什么问题 / 一个带数字的最小例 / 最容易和谁搞混。

## 装法

### DeepSeek Harness（DSH）

```bash
mkdir -p ~/.dsh/skills/teach-by-analogy
curl -o ~/.dsh/skills/teach-by-analogy/SKILL.md \
  https://raw.githubusercontent.com/<your-name>/teach-by-analogy/main/SKILL.md
```

把 `<your-name>` 换成实际用户名。装完**刷新页面或新开会话**——`/` 菜单的技能目录是按会话缓存的，不刷新看不到新技能。（或者直接手打 `/teach-by-analogy` 发送，不用等菜单。）

### Claude Code

```bash
mkdir -p ~/.claude/skills/teach-by-analogy
cp SKILL.md ~/.claude/skills/teach-by-analogy/SKILL.md
```

### 其他运行时

任何读 `skills/<kebab-name>/SKILL.md` 的运行时都能直接用——frontmatter 只有 `name` 和 `description` 两个键，没有私有字段。

## 用起来长什么样

直接说人话就行，不需要记命令：

- 「图卷积和自注意力到底在干嘛，打个比方」
- 「这句我没看懂：`softmax(QKᵀ/√dₖ)V`」
- 「链式法则为什么要乘起来」
- 「讲人话」

### 示范片段（自注意力）

**先看一个例子**：你去菜市场买苹果。手里有一张清单（想要脆的、甜的、便宜的）。每个摊位挂着牌子，写着「我家苹果什么样」。你挨个把清单和牌子对一遍，越对得上的摊位，你越愿意多买他家的。最后拎回家那袋苹果，是按「你有多信这家」的比例从好几家混出来的——不是只买一家，也不是平均买。

| 生活场景 | 对应物 | 为什么对得上 |
|---|---|---|
| 你的需求清单 | Query (Q) | 都是「我想要什么」的表示，用来去比对 |
| 摊位挂的牌子 | Key (K) | 都是「我有什么」的表示，等着被比对 |
| 摊位实际的苹果 | Value (V) | 都是真正被取走并混合的内容 |
| 按分数分配购买预算 | softmax | 一组非负数、加起来等于 1 的权重 |

**同一个骨架换壳**：图卷积也是「从别人那儿拿东西再混合」，但「听谁的」由**图的连接**定死（只跟邻居、按度数加权）；注意力里「听谁的」由**内容像不像**现场算。骨架相同、约束不同，差别一眼就出来。

完整示范见 [`SKILL.md`](./SKILL.md) 的附录 A（自注意力）和附录 B（链式法则）。

## 边界

这个 skill 不承诺「一定能找到好比方」。找不到时它会**直说**「这里没有能对上的生活场景」，然后退回**最小数字例子 + 反例对照**——把公式代进 2×2 矩阵、把概率代成具体人数。硬凑一个漂亮比方，比承认找不到更糟。

高风险领域（医疗、法律、金融、安全）里，比方只用来辅助理解机制，结论仍须给精确表述和适用条件。
